 3D 高斯泼溅本地渲染呈现方案
  
 Context

 方案文档 (docs/三维重建数据采集和场景构建方案.md) 描述了 PIX4Dmatic 高斯泼溅 PLY 导出能力，并指出当前 DualCanvasViewer "已有 DRC
 高斯泼溅检测逻辑"。实际探索发现：

 - test 项目 (D:/交付/test/) 中的 dual-canvas-viewer.mjs 已实现简化版高斯泼溅渲染（ShaderMaterial + THREE.Points 点精灵），但
 DualCanvasViewer.loadThreeModel() 只接受 GLB/GLTF，无法通过 UI 加载 PLY/DRC 高斯文件。
 - draco3dgs-tsc-frontonly-V2 项目 (D:/交付/draco3dgs-tsc-frontonly-V2/) 是完整的 3DGS Web 渲染方案，含自定义 Draco WASM（支持
 SCALE_3DGS、ROTATION_3DGS、OPACITY_3DGS、FEATURE_DC_3DGS、FEATURE_REST_3DGS 五类 3DGS 属性）、Express 开发服务器、Vue 3 前端。

 本方案旨在提供"立即可用 + 深度集成"两层次的本地渲染呈现路径。

 方案设计

 路径一（立即可用）：启动 draco3dgs 作为独立高斯泼溅查看器

 目标：直接用 draco3dgs 项目的 Express + Vue 3 前端，在本地浏览器中查看高斯泼溅 PLY/DRC 文件。

 步骤：

 1. 验证 draco3dgs 项目可运行
   - 进入 D:/交付/draco3dgs-tsc-frontonly-V2/draco3dgs-tsc-frontonly-V2/
   - 运行 npm install（确保依赖安装，package.json 依赖: express, three, cors）
   - 运行 node server.js 启动开发服务器（端口 3000）
   - 浏览器访问 http://localhost:3000
 2. 放置测试数据
   - 将高斯泼溅 PLY 文件放入 datatool/ply/
   - 或将 DRC 文件放入 datatool/drc/
   - 服务器自动通过 /api/ply-models 和 /api/drc-models 暴露文件列表
 3. 验证渲染效果
   - 前端 ThreeViewer 组件自动检测 3DGS 属性 → 使用 createGaussianSplatMaterial 渲染
   - 确认 OrbitControls 交互、点云可视化正常

 涉及文件：
 - draco3dgs-tsc-frontonly-V2/server.js — 可能需要检查端口占用（若 3000 被 test 项目占用则换端口）
 - draco3dgs-tsc-frontonly-V2/public/components/ThreeViewer.vue — 高斯泼溅渲染核心

 路径二（深度集成）：增强 test 项目的 DualCanvasViewer 高斯渲染能力

 目标：让 test 项目的 DualCanvasViewer 能够直接通过 UI 加载和渲染高斯泼溅 PLY/DRC 文件，实现与 Cesium 地球层的叠加联动。

 步骤：

 1. 复制 draco3dgs 自定义 WASM 到 test 项目
   - 源：draco3dgs-tsc-frontonly-V2/draco3d/draco3d/（draco_decoder.wasm, draco_decoder.js, draco_encoder.wasm, draco_encoder.js,
 attributes.js）
   - 目标：test/public/draco3d/draco3d/（与现有 /draco3d/draco3d/ 路径对齐，或新建路径）
   - 这些 WASM 文件包含自定义的 3DGS 属性支持，区别于标准 Three.js DRACOLoader 使用的通用 Draco WASM
 2. 扩展 DualCanvasViewer.loadThreeModel() 支持 PLY/DRC
   - 文件：test/src/components/functions/lib/dual-canvas-viewer.mjs
   - 位置：loadThreeModel() 方法（约第 10821 行）
   - 改动：移除当前"仅接受 GLB/GLTF"的限制，增加 PLY/DRC 分支
   - 复用已有的 loadSingleModel() → loadDrcModel() / loadWithLoader(plyLoader) 逻辑
   - 确保加载前检查 3DGS 属性 → 自动路由到高斯泼溅渲染管线
 3. 改进高斯泼溅 Shader（可选优化）
   - 当前 shader 点大小被限制到 max 1.0，显示效果偏小
   - 参考 draco3dgs 项目的 shader 参数，适当增大点大小和抗锯齿范围
   - 文件：dual-canvas-viewer.mjs 中 createGaussianSplatMaterial() 方法（约第 7300 行）
 4. 添加 Cesium 坐标联动
   - 当前高斯泼溅在 Three.js 局部坐标系渲染，需要与 Cesium 地球的 ECEF 坐标对齐
   - 复用已有的 convert-b3dm-ECEF-to-glb.js 中的坐标转换逻辑（PCA 贴地对齐 + _geolocation 元数据）
   - 对高斯 PLY 文件注入地理元数据后，DualCanvasViewer 可自动进行地理定位

 涉及文件：
 - test/src/components/functions/lib/dual-canvas-viewer.mjs — 核心改动文件
 - test/public/draco3d/draco3d/ — 新增自定义 WASM 文件
 - test/index.html — 如需要，添加 Draco WASM 路径配置

 路径三（备选）：在 test 项目中嵌入 iframe 联动

 如果深度集成工作量大，可采用更轻量的方案：
 - draco3dgs 作为独立服务运行
 - test 项目通过 iframe 嵌入 draco3dgs 页面
 - 通过 postMessage 实现两者之间的视口同步（Cesium 相机 ↔ Three.js 相机）

 推荐实施顺序

 1. 先执行路径一 — 验证 draco3dgs 能否正常启动和渲染（15 分钟内可完成）
 2. 再执行路径二 — 增强 test 项目的高斯渲染能力（核心改动）
 3. 路径三维持为备选 — 仅在前两者时间不足时采用

 验证方法

 路径一验证

 - 启动 node server.js 后浏览器打开 localhost:3000
 - 上传或选择高斯泼溅 PLY/DRC 文件
 - 确认 3DGS 属性被检测并通过自定义 shader 渲染为彩色点云
 - 确认 OrbitControls（旋转/缩放/平移）正常

 路径二验证

 - 启动 test 项目开发服务器
 - 在 DualCanvasViewer UI 中通过文件选择器加载 .ply 高斯文件
 - 确认文件被正确解析，3DGS 属性被提取，点云在 Three.js 层渲染
 - 确认与 Cesium 地球底图的叠加显示、坐标对齐
 - 对比 draco3dgs 独立查看器的渲染效果，确认一致
