  ├──────────┼──────────────────────────────────────────────────────────────────┼────────────────────────────────────────────┤
  │ 树结构   │ 固定四叉树：每个瓦片固定4个子节点                                │ HLOD                                       │
  │          │                                                                  │ 层次细节图：任意树结构，子节点数不固定     │
  ├──────────┼──────────────────────────────────────────────────────────────────┼────────────────────────────────────────────┤
  │ 覆盖范围 │ 全球均匀剖分：GeographicTilingScheme，Level N 有 2^(N+1)×2^N     │ 仅覆盖模型区域：只生成有数据的瓦片         │
  │          │ 个瓦片                                                           │                                            │

  └──────────┴───────────────────────────────────────────────────┴──────────────────────────────────────────────────────┘

  4. 核心差异总结

  地形 LOD：全球四叉树，均匀剖分，几何误差靠公式算
           ┌──┬──┐
           │  │  │  ← 每个 tile 细分成 4 个
           ├──┼──┤
           │  │  │     所有区域都剖分（包括海洋占位瓦片）
           └──┴──┘

  3D Tiles HLOD：局部层次树，非均匀，几何误差精确指定
           ┌─┐
           │ │        ← 近处加载精细模型
         ┌─┼─┼─┐
         │ │ │ │      ← 远处加载简化模型
         └─┴─┴─┘         不覆盖的区域没有瓦片
         skipLevelOfDetail 可跳过中间层直接加载最佳层

  5. 为什么之前地形 LOD 有问题而 3D Tiles 没有

  地形 LOD 的复杂性在于全球剖分 + Y 坐标转换：

  - layer.json 要同时正确配置 scheme、available、format
  - jLe 默认做 TMS Y 翻转，而你的瓦片目录用的是 Cesium 原生 Y 约定
  - available 数组的 Y 值必须用 TMS 约定（你之前用了目录 Y）→ Level 2+ 被阻塞
  - 占位瓦片（全零高程）的 childMask 为 0 → 无法展开子节点

  3D Tiles 则简单得多：
  - 只有一个 tileset.json，树结构自描述
  - 坐标在模型自身坐标系中，不涉及 TMS/Geographic 转换
  - 不存在"占位瓦片"概念，没数据就不生成
