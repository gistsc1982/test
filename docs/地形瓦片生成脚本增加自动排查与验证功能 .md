 Plan: 地形瓦片生成脚本增加自动排查与验证功能
  
 Context

 用户发现地形不显示的根因是瓦片坐标系统不匹配。虽然当前脚本 generate-terrain-tiles-heightmap4old.js 使用正确的 GeographicTilingScheme
 公式（X 坐标用 2^(level+1)），但历史数据可能由错误公式生成（X 坐标用 2^level），导致运行时 Cesium 请求的瓦片坐标（如 level 10
 X=836）与磁盘文件（level 10 X=1672）不一致，地形永远无法加载。

 需要在生成脚本中增加自动排查机制，在生成前/后检测并报告 tiling scheme 不匹配问题。

 技术背景

 坐标公式差异

 ┌───────────────────────────────┬────────────────────────────────┬───────────────────┬────────────────┐
 │         Tiling Scheme         │           X 坐标公式           │ Level 10 X 最大值 │ 吉安114°E 的 X │
 ├───────────────────────────────┼────────────────────────────────┼───────────────────┼────────────────┤
 │ GeographicTilingScheme (正确) │ floor((lon+180)/360 * 2^(N+1)) │ 2047              │ 1672           │
 ├───────────────────────────────┼────────────────────────────────┼───────────────────┼────────────────┤
 │ WebMercator-style (错误)      │ floor((lon+180)/360 * 2^N)     │ 1023              │ 836            │
 └───────────────────────────────┴────────────────────────────────┴───────────────────┴────────────────┘

 两者正好相差 2 倍。

 当前代码状态

 - 脚本 lonToTileX 公式正确（Math.pow(2, level + 1)）✓
 - layer.json available 数据正确 ✓
 - 磁盘 tile 坐标与公式一致 ✓
 - LocalTerrainProvider.js 使用 GeographicTilingScheme ✓
 - GeoTiffTerrainProvider.js 使用 GeographicTilingScheme ✓

 为什么还需要增强

 虽然当前脚本公式正确，但如果用户用其他工具生成 terrain
 数据，或者脚本曾被误修改，就会产生隐蔽的坐标不匹配。增加自动验证可以从源头杜绝问题。

 实施方案

 1. 新增 Tiling Scheme 定义模块

 在 lonToTileX/latToTileY 函数之后新增：

 const TILING_SCHEMES = {
   geographic: {
     name: 'GeographicTilingScheme (EPSG:4326)',
     description: 'Cesium 默认地理瓦片方案',
     xtilesAtLevel: (level) => Math.pow(2, level + 1),  // 2^(N+1)
     ytilesAtLevel: (level) => Math.pow(2, level),       // 2^N
     lonToX: (lon, level) => Math.floor((lon + 180) / 360 * Math.pow(2, level + 1)),
     latToY: (lat, level) => Math.floor((90 - lat) / 180 * Math.pow(2, level)),
     xToLon: (x, level) => x / Math.pow(2, level + 1) * 360 - 180,
     yToLat: (y, level) => 90 - (y + 1) / Math.pow(2, level) * 180,
   },
   'web-mercator': {
     name: 'WebMercatorTilingScheme (EPSG:3857)',
     description: 'Web 墨卡托瓦片方案（相同经度 X 坐标 = geographic 的一半）',
     xtilesAtLevel: (level) => Math.pow(2, level),       // 2^N
     ytilesAtLevel: (level) => Math.pow(2, level),       // 2^N
     lonToX: (lon, level) => Math.floor((lon + 180) / 360 * Math.pow(2, level)),
     latToY: (lat, level) => Math.floor((90 - lat) / 180 * Math.pow(2, level)),
     xToLon: (x, level) => x / Math.pow(2, level) * 360 - 180,
     yToLat: (y, level) => 90 - (y + 1) / Math.pow(2, level) * 180,
   }
 };

 2. 新增验证函数

 2a. detectTilingScheme(bounds, outputDir)

 分析磁盘上的 tile 坐标，反推使用了哪种 tiling scheme：
 - 读取最低层和最高层的 tile 目录
 - 对每个存在的目录名（X坐标），用两种 scheme 反算经度
 - 比对 bounds，判定匹配哪种 scheme
 - 返回检测结果：{ detected, confidence, evidence }

 2b. validateSelfConsistency(outputDir, minZoom, maxZoom)

 检查瓦片四叉树自洽性：
 - 对 level N 的每个 tile (x, y)，检查 level N-1 的父 tile (floor(x/2), floor(y/2)) 是否存在
 - 对 level N 的每个 tile (x, y)，检查 level N+1 的四个子 tile 是否都存在
 - 报告任何不连续或孤儿 tile

 2c. validateCesiumCompatibility(outputDir, bounds, scheme)

 模拟 Cesium 请求流程：
 - 对 bounds 内的一组采样点（四角和中心），计算在指定 scheme 下的坐标
 - 检查对应的 .terrain 文件是否存在
 - 如果 100% 文件缺失而另一种 scheme 的坐标存在文件，明确报告 scheme 不匹配
 - 输出诊断表格（像用户做的那样）

 2d. printDiagnosticReport(bounds, outputDir, scheme)

 输出可供排查的详细信息：
 - 每个 level 的 X/Y 范围
 - bounds 中心点在每个 level 的坐标（对比两种 scheme）
 - 实际存在的 tile 坐标列表
 - 如果检测到不匹配，给出明确的修复建议

 3. 新增 CLI 选项

 在 main() 函数开头增加参数解析：

 node generate-terrain-tiles-heightmap4old.js [选项]
   --validate              仅验证现有数据，不重新生成
   --tiling-scheme <name>  指定 tiling scheme (geographic|web-mercator)，默认 geographic
   --check-compatibility   生成后验证 Cesium 兼容性（默认开启）
   --no-check              跳过所有验证
   --diagnose              打印瓦片坐标诊断报告后退出

 4. main() 修改

 在生成流程中插入验证步骤：

 main():
   1. 解析 CLI 参数
   2. [--diagnose] 打印诊断报告，退出
   3. [--validate] 验证现有数据，打印报告，退出
   4. 读取 GeoTIFF（同现有流程）
   5. 打印 tiling scheme 信息
   6. [如果输出目录已存在] 调用 detectTilingScheme() 检测已有数据
      - 如果检测到的 scheme 与预期不一致 → 警告 + 询问
   7. 生成 tiles（同现有流程）
   8. [默认] 调用 validateSelfConsistency()
   9. [默认] 调用 validateCesiumCompatibility()
   10. 如果验证失败 → 打印错误 + 修复建议
   11. 生成 layer.json（同现有流程，增加 scheme 字段）

 5. layer.json 增强

 在 layer.json 中增加 tilingScheme 字段，显式声明使用的方案：
 {
   "tilingScheme": "geographic",
   ...
 }

 验证方法

 1. 正常生成验证: 运行 node scripts/generate-terrain-tiles-heightmap4old.js，确认末尾输出验证通过
 2. 诊断模式: 运行 node scripts/generate-terrain-tiles-heightmap4old.js --diagnose，确认输出包含坐标对比表
 3. 验证模式: 运行 node scripts/generate-terrain-tiles-heightmap4old.js --validate，确认输出现有数据状态
 4. 模拟错误场景: 手动将输出目录中 level 10 的目录 1609/ 重命名为 804/，运行 --validate，确认检测到 scheme 不匹配并给出修复建议
 5. WebMercator 方案: 运行 node scripts/generate-terrain-tiles-heightmap4old.js --tiling-scheme web-mercator，确认生成的坐标与 2^N
 公式一致
